# Go SVT Maroc — علوم الحياة والأرض

منصة تعليمية بالعربية والفرنسية للمستويات TC و1BAC و2BAC، تتضمن مكتبة موارد، اختبارات، فضاء التلميذ، الأقسام، وإدارة المحتوى ومجتمع الأساتذة.

## مساحتي — منصة التعلّم المتقدمة

واجهة عربية حديثة بحسب المستوى والمسلك، مع مكتبة فعلية ودروس خاصة وملفات مرفوعة، تجارب افتراضية موجهة، تدريبات محلية مشروحة، اختبارات مُدارة على الخادم، خطة وملاحظات وتركيز، وإدارة تحريرية لبنوك الأسئلة والموارد.

```sh
npm ci --ignore-scripts
npm run build:catalog
npm run dev:student
```

المعاينة المحلية واضحة التسمية ولا تتصل بالإنتاج. تفعيل الإدارة والتقييم الخادمي يحتاج الترحيل `20261126000100_student_learning_platform.sql` على **المشروع الرئيسي** بعد تجهيز مخططه السابق واختبار staging. التفاصيل والحدود في [STUDENT_PLATFORM_AR.md](docs/STUDENT_PLATFORM_AR.md).

## البنية الحالية

- **الواجهة:** HTML/CSS/JavaScript، منشورة عبر GitHub Pages. لا تحتاج مكتبة الواجهة إلى bundler.
- **البناء المنشور:** Jekyll يحوّل `content.json` من قالب Liquid إلى فهرس JSON. تولّد أدوات `_tools/` صفحات SEO وكتالوج الصور.
- **المشروع الرئيسي في Supabase:** المصادقة، الملفات الشخصية، المستوى والمسلك المعتمدان، تقدم التلميذ وملاحظاته وخطته ومفضلاته، الدروس الخاصة، الأقسام ولوحة المدير.
- **مجتمع الأساتذة:** مشروع Supabase مستقل، وإعداد منفصل في `teacher-community-config.js`. لا تدمج حساباته أو ترحيلاته مع المشروع الرئيسي.
- **التخزين المحلي:** ذاكرة عمل/نسخة مؤقتة خاصة بالحساب، وليس نظام المصادقة. بعض بيانات العرض مثل موضع القراءة تبقى محلية. الملفات العامة المحفوظة صراحةً تدعم القراءة دون اتصال؛ الحسابات والخدمات السحابية تحتاج اتصالًا.

## تشغيل محلي آمن

المتطلبات: **Node.js 22+** و**Python 3.10+**. إصدارات اعتماديات الاختبار مثبتة في `package-lock.json`.

```sh
npm ci --ignore-scripts
npm run dev
```

افتح `http://127.0.0.1:8000/`. لا تفتح `index.html` مباشرةً بصيغة `file://`، ولا تستخدم خادم ملفات بسيطًا يعيد قالب `content.json` دون تحويله.

خادم التطوير:
- يولّد فهرس `content.json` من الملفات الموجودة محليًا دون تعديلها.
- **يعطّل الاتصال بالمشروعين الإنتاجيين افتراضيًا**.
- لا يحاكي صفحات SEO المولّدة؛ التحقق من ناتج Jekyll يتم في مسار النشر.
- لا يعرض `.git` أو `node_modules` أو إعداداتك المحلية أو SQL.

لاختبار الحسابات على مشاريع تطوير مستقلة، انسخ `config.local.example.json` إلى `config.local.json` وأدخل عناوين مشاريع الاختبار ومفاتيحها العامة فقط. هذا الملف مستبعد من Git ومن النشر. لا تستخدم بيانات تلاميذ حقيقية في الاختبارات.

للمعاينة في حاوية أو بيئة بعيدة:

```sh
npm run dev -- --host 0.0.0.0 --port 8000
```

## الاختبارات

```sh
npm test
npx playwright install --with-deps chromium
npm run test:browser
python3 scripts/check-site.py
python3 scripts/check-basic-accessibility.py
python3 scripts/check-migration-rls.py
python3 scripts/check-teacher-community-security.py
python3 scripts/check-seo-indexing.py
python3 scripts/migration-plan.py --check
```

- اختبارات Node تغطي الاستعادة الجزئية، الحذف، الحسابات، السباقات، CSV، القراءة دون اتصال وترتيب السكربتات.
- PGlite يشغّل الترحيلات الإضافية على **مخطط اختبار اصطناعي** للتحقق من SQL وRLS والمعاملات؛ ليس نسخة من قاعدة الإنتاج.
- Playwright يشغّل المتصفح وخدمة محلية، ويمنع طلبات الإنتاج ويستبدل خدمات الحسابات ببيانات وهمية. يشغّل أيضًا `AUDIT_TEST_SUITE.js` الموجودة في المشروع. صفحة التدقيق وحزمتها مستبعدتان من ناتج الإنتاج، وتبقيان متاحتين محليًا.
- نجاح هذه الاختبارات لا يثبت حالة سياسات أو buckets الإنتاجية. يلزم اختبار staging بعد تطبيق الترحيلات.

## قواعد البيانات والترحيلات

**تحذير: المخطط التأسيسي الكامل للمشروع الرئيسي غير موجود في المستودع.** لا يكفي تطبيق جميع الملفات الموجودة على مشروع فارغ. ولا يجوز تمرير مجلد الترحيلات المشترك كله إلى أحد المشروعين.

اعرض خطة المشروع المقصود فقط؛ هذه الأوامر لا تتصل بأي قاعدة ولا تنفّذ SQL:

```sh
python3 scripts/migration-plan.py --project main
python3 scripts/migration-plan.py --project teacher-community
```

التعيين الصريح موجود في `supabase/project-manifest.json`. راجع:
- [متطلبات قاعدة البيانات وإجراء الترقية](docs/DATABASE_DEPLOYMENT_AR.md)
- [ربط المشروع الرئيسي](SUPABASE_CONNECTION_AR.md)
- [إعداد مجتمع الأساتذة](TEACHER_COMMUNITY_SETUP_AR.md)
- [فضاء الأقسام](TEACHER_CLASSROOM_SETUP_AR.md)

ترحيلات `20261125000100` و`20261125000200` و`20261125000300`، وترحيل المنصة `20261125000400`، مخصصة **للمشروع الرئيسي فقط**، وتحتاج مخططه السابق. لا ينفّذها GitHub Actions تلقائيًا. اختبرها على staging وخذ نسخة احتياطية قبل أي تطبيق إنتاجي.

## النشر

`validate-site.yml` يفحص المصدر ويشغّل اختبارات السلوك وSQL الاصطناعي والمتصفح. يبني `pages.yml` الالتزام المحدد بواسطة `github.sha`، ثم يفحص ناتج `_site` قبل رفعه.

لا يُجرى `git pull` أو rebase في منتصف البناء. حفظ الاختبارات المولّدة آليًا، إذا توفرت مفاتيح مولّد المحتوى، يجري بعد فحص ناتج البناء؛ يفشل الدفع بأمان إن تقدّم `main` بالتوازي، دون استبدال الشيفرة الجاري نشرها. إعداد مفاتيح مولّد المحتوى اختياري وموجود في أدلة `_tools/`.

تُحسب بصمة إصدار Service Worker من ملفات الواجهة المبنية، مع الاحتفاظ بمخبأ PDF المحفوظ يدويًا. بعد بناء Jekyll يمكن فحص الناتج بهذه الأوامر:

```sh
python3 _tools/build_service_worker.py _site
npm run check:built
```

## إضافة محتوى

ضع الملف في مساره الدراسي، مثل:

```text
cours/francais/TC/TCS/lesson.pdf
```

راجع [HOW_TO_ADD_FILES.md](HOW_TO_ADD_FILES.md). مكتبة الملفات المرفوعة من لوحة المدير والدروس الخاصة تستخدم Supabase، ولا تستلزم إعادة كتابة ملفات المستودع.
