# «مساحتي» — منصة التعلّم المتقدمة

## ما أُنجز

هذه نسخة فعلية من واجهة «مساحتي» وليست صورًا ثابتة. تحتفظ بوظائف الحساب والمزامنة السابقة وتضيف:

- لوحة تعلم عربية متجاوبة، بخط Cairo محلي ورسوم مفاهيمية وصورة زخرفية محسّنة بصيغة WebP.
- تخصيص الموارد وفق `student_academic_profiles` المرتبط بالحساب. لا يوجد في الواجهة الإنتاجية تبديل حر للمستوى أو المسلك.
- فهرس يُبنى من الملفات الفعلية، مع حذف النسخ المتطابقة داخل النطاق نفسه، وترتيب الدروس بحسب الوحدة والفصل حين يحمل الاسم هذه المعلومات.
- إدراج الدروس الخاصة المنشورة، والملفات المرفوعة سابقًا إلى `site-content`، والموارد التحريرية الجديدة، مع المحافظة على مفاتيح تقدم الملفات المرفوعة ومفضلة الدروس الخاصة.
- بحث بالعناوين واللغة والنوع والمفضلة؛ عارض PDF للملفات المحلية وروابط فتح/تحميل للموارد الأخرى.
- تأكيد صريح لإنجاز الدرس. فتح الملف لا يعني أنه أُنجز.
- مسار دراسي، خطة يومية مقترحة قابلة للتعديل، مهام مؤرخة، دفتر ملاحظات، وجلسات تركيز 25 أو 50 دقيقة.
- ثلاث تجارب افتراضية: تزاوج أحادي الهجين بسيادة تامة، نموذج نوعي للتركيب الضوئي، ونموذج مبسط لخصائص التربة. توجد أدوات تحكم ودفتر حالات وتصدير CSV.
- تدريبات من بنوك الأسئلة الموجودة، إضافة إلى تدريبات عربية ومهارات علمية مشتركة. تصحيحها المحلي واضح وليس نقطة رسمية.
- أرشيف أوراق الامتحانات الفعلية وتصحيحاتها عندما يمكن ربطها بالمستوى والمسلك والسنة والدورة. الملفات الأصلية لم تُعدّل، ولا تُختلق أوراق رسمية لسد نقص المحتوى.
- اختبارات مُدارة بتوقيت وتصحيح على الخادم، ولقطة ثابتة للأسئلة لكل محاولة، وحفظ متسلسل للإجابات، وإعادة إرسال آمنة لعملية التسليم.
- تبويب جديد في `admin.html` لإدارة الموارد الإضافية وبنوك الأسئلة: مسودات، تحديد الجمهور، استيراد JSON، معاينة التصحيح، نشر بعد تأكيد المراجعة، وسجل نتائج خادمي مع تصدير النتائج المحمّلة.
- إبقاء فضاء القسم والواجبات والتواصل الحالي، وإبقاء رابط للأدوات الكلاسيكية بدل حذفها.

## تشغيل التطوير والمعاينة

```sh
npm ci --ignore-scripts
npm run build:catalog
npm run dev:student
```

افتح `http://127.0.0.1:8000`. في بيئة معاينة شبكية يمكن إضافة `-- --host 0.0.0.0`.

المعاينة صفحة منفصلة اسمها `student-preview.html`، عليها شريط واضح يبين أنها محلية. يبدأ التقدم دون نقط أو إنجازات مختلقة؛ كل ما يظهر لاحقًا ينتج عن تفاعل المتصفح نفسه. تبديل المسلك في شريط المعاينة يغيّر ملفًا تجريبيًا فقط، ولا يغيّر حسابًا حقيقيًا. لا تُحمّل المعاينة عميل Supabase، ولا تتصل بقاعدة الإنتاج.

`student-preview.html` و`student-platform-preview.js` مستبعدان من ناتج GitHub Pages. عند النشر الحقيقي يعمل التخصيص من حساب مسجّل في `index.html#student-space`.

لتشغيل الموقع العام محليًا:

```sh
npm run dev
```

المصادقة الإنتاجية معطّلة افتراضيًا في خادم التطوير. إعداد مشروع staging يتم بواسطة `config.local.json` غير المتتبع في Git؛ راجع ملف المثال ودليل قاعدة البيانات. لا تضع `service_role` أو كلمات مرور قاعدة البيانات في ملفات المتصفح.

## تفعيل الخدمات السحابية

1. راجع [DATABASE_DEPLOYMENT_AR.md](DATABASE_DEPLOYMENT_AR.md)، وتأكد من هوية المشروع الرئيسي ومن اكتمال مخططه السابق. المخطط التأسيسي الناقص لم يُختلق.
2. طبّق ترحيلات مراجعة الإصلاحات `20261125000100` و`20261125000200` و`20261125000300` إذا لم تكن مطبقة، بعد اختبار staging.
3. راجع وطبّق على **المشروع الرئيسي فقط**:
   `supabase/migrations/20261126000200_student_learning_platform.sql`.
4. الترحيل يتحقق أولًا من وجود `profiles` و`student_academic_profiles`، ثم ينشئ:
   - `learning_resources`: إضافات تحريرية منشورة لجمهور محدد.
   - `learning_assessments`: بيانات البنوك وحالتها وإصدارها.
   - `learning_questions`: مفاتيح إجابة يقرأها المدير فقط.
   - `learning_attempts`: المحاولات ولقطاتها الخاصة؛ التلميذ لا يملك كتابة النقطة أو قراءة لقطة مفاتيح الإجابة.
   - `student_learning_events`: أنشطة المختبر والتركيز الخاصة بصاحب الحساب.
5. تحقق في staging بحسابين من مسلكين مختلفين وحساب مدير، عبر Auth وPostgREST الفعليين، لا باختبار SQL وحده.
6. انشر الواجهة بعد نجاح إعداد قاعدة البيانات، وأعد تحميل التبويبات القديمة.

راجع أيضًا:

```sh
python3 scripts/migration-plan.py --project main
python3 scripts/migration-plan.py --check
```

لا تُنفّذ الترحيل على مشروع مجتمع الأساتذة المستقل. لم تُنفّذ هذه الحزمة أي تغييرات على قاعدة الإنتاج.

## آلية التقييم

### تدريبات المراجعة

بنوك المستودع تستعمل `reponse` بدءًا من 1. يُحوّل المحرك ذلك إلى فهرس داخلي بدءًا من 0 مع تحقق صريح، ولا يخمّن الإجابة عند فساد البنك. تُحفظ المحاولة للجهاز والحساب، وتُضاف إلى سجل التدريب المعتاد عندما يكون متاحًا. لا يُقدّم هذا المسار باعتباره تقييمًا محميًا من التعديل أو نقطة وطنية.

### الاختبارات المُدارة

- يبدأ الاختبار عبر RPC يفحص هوية الجلسة والمستوى والمسلك وحالة النشر.
- يحدد الخادم موعد النهاية. إعادة تحميل الصفحة لا تمنح وقتًا جديدًا.
- الأسئلة محفوظة كلقطة في المحاولة؛ تعديل بنك الأسئلة لاحقًا لا يغيّر تصحيح محاولة بدأت سابقًا.
- لا تُرسل مفاتيح الإجابة أو التفسيرات الخاصة مع أسئلة البداية.
- تحمل طلبات حفظ الإجابات رقمًا متزايدًا؛ لا يستبدل طلب متأخر إجابات أحدث.
- بعد انتهاء الأجل تُصحح آخر إجابات وصلت إلى الخادم، لا حمولة متأخرة تُرسل بعد الوقت.
- التسليم متكرر الإرسال بأمان: المحاولة المكتملة تعيد نتيجتها نفسها، ولا تُصحح مرة ثانية بحمولة مختلفة.
- لا تُعرض نتيجة خادمية إذا فشل الطلب أو لم تصل نتيجة صحيحة البنية.

الحجب عبر API لا يجعل النظام مراقبة امتحانات أو شهادة رسمية، ولا يمنع توفر أجوبة أسئلة منقولة من مصادر عامة. المحاولات المنقطعة قد تبقى غير مكتملة إلى أن يعود صاحبها ويستكمل التسليم؛ لم تُضف مهمة إنتاجية مجدولة لإنهائها تلقائيًا.

## إدارة المحتوى

بعد تسجيل الدخول بصفة مدير، افتح «منصة التعلّم والاختبارات» في لوحة الإدارة.

- الموارد الجديدة تُصنّف بحسب المستوى والمسالك واللغة. ملفات المستودع نفسها تُفهرس تلقائيًا، وإخفاء إضافة تحريرية لا يحذف ملفًا عامًا من GitHub أو Storage.
- يمكن حفظ بنك فارغ كمسودة، لكن النشر يتطلب 3–60 سؤالًا صالحًا، مع تفسير لكل إجابة، وتأكيد المراجعة التحريرية.
- صيغة الاستيراد هي صيغة بنوك المستودع (`question`, `choix`, `reponse`, `explication`) أو الصيغة الداخلية المكافئة. لا تستخدم ملف المثال كأنه اختبار وطني.
- تعديل بنك قائم يستخدم رقم إصدار؛ إذا عُدّل في جلسة أخرى يُرفض استبداله بصمت.
- الأرشفة تمنع محاولات جديدة ولا تمسح نتائج قديمة. لا تفترض وجود نظام مراقبة صفية أو إدارة دورات مدرسية كاملة ضمن هذه الدفعة.
- تصدير النتائج يصف بوضوح المحاولات المحمّلة فقط، مع زر تحميل المزيد. لا يتضمن درجات التدريب المحلي على أنها نتائج خادمية.
- عند انقطاع الاستجابة أثناء إنشاء مورد أو بنك، حدّث القائمة للتحقق قبل إعادة الإنشاء.

## المحتوى والرسوم والحدود

- الفهرس الحالي مبني على الموارد الموجودة؛ بعض المسالك قليلة المحتوى. ظهور أدوات مشتركة لا يعني اكتمال برنامج ذلك المسلك.
- التجارب نماذج تعليمية معلنة الافتراضات، وليست قياسات مخبرية فعلية. وراثة الصفة الواحدة لا تعمم على كل الصفات، وأرقام النفاذية والتركيب الضوئي نسبية.
- صورة الترحيب مولّدة لأغراض زخرفية، والرسوم داخل البطاقات تخطيطية. لا تقدم على أنها صور مجهرية أو توثيق تجربة.
- ملفات الخط مرخصة وفق SIL OFL؛ الترخيص موجود في `assets/student-platform/FONT-LICENSE.txt`.
- الملاحظات والمهام محلية أولًا وتزامنها الخدمات الحالية عند توفرها. الاختبارات الخادمية تحتاج اتصالًا؛ لم تُدَّعَ مصادقة كاملة دون إنترنت.
- التصدير الشخصي لقطة من بيانات الجهاز والنتائج المحمّلة، وليس نسخة احتياطية كاملة من Supabase. لا يصدّر رموز المصادقة.
