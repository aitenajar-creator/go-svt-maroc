# إعداد مشروع مجتمع الأساتذة — GO SVT Maroc

## بنية مستقلة فعلياً
مجتمع الأساتذة يعمل على مشروع Supabase ثانٍ مستقل عن المشروع الحالي للمدير والتلاميذ وفضاء الأقسام. هذا يتيح إنشاء حساب أستاذ مستقل حتى إذا استعمل الأستاذ البريد نفسه في فضاء التلميذ.

لا تغيّر إعدادات أو جداول مشروع Supabase الحالي.

## 1. إنشاء مشروع Supabase جديد
1. من لوحة Supabase أنشئ مشروعاً جديداً باسم مثل `gosvt-teacher-community`.
2. اختر كلمة مرور قوية لقاعدة البيانات واحتفظ بها في مكان آمن.
3. من Project Settings → API انسخ Project URL ومفتاح Publishable (أو anon public key).
4. افتح ملف `teacher-community-config.js` في هذا المستودع، واستبدل القيمتين النموذجيتين بعنوان المشروع الجديد ومفتاحه العام. لا تضع service_role أو secret key في هذا الملف.

## 2. إعداد Auth
في المشروع الجديد:
- Authentication → Providers → Email: فعّل البريد الإلكتروني.
- Authentication → URL Configuration: اجعل Site URL هو `https://gosvtmaroc.com`.
- أضف `https://gosvtmaroc.com/teacher-community.html` إلى Redirect URLs (وأضف رابط المعاينة إن احتجته).

## 3. إنشاء الجداول والتخزين
1. افتح SQL Editor في مشروع الأساتذة الجديد.
2. انسخ ونفّذ الملف `supabase/migrations/20261111000100_teacher_community_library.sql` كاملاً.
3. ينشئ السكربت جدول المشرفين والأعضاء والموارد، وسياسات RLS، وbucket خاصاً باسم `teacher-community`.
4. لا تنفّذ هذا الملف في مشروع Supabase الحالي الخاص بالتلاميذ.
5. بعد تنفيذ ملف الإنشاء الأساسي (مرة واحدة)، نفّذ ملف التقوية الأمنية `supabase/migrations/20261111000200_teacher_community_storage_read_hardening.sql` في SQL Editor للمشروع الجديد نفسه. هذا الملف يحدّث سياسة قراءة Storage حتى لا يتمكن من تنزيل الملفات إلا صاحبها أو المدير أو عضو مقبول عندما يكون الملف منشوراً ومشتركاً.
6. القائمة أعلاه لا تغني عن بقية تحديثات الصلاحيات والتدقيق. اعرض القائمة الكاملة المرتبة بواسطة `python3 scripts/migration-plan.py --project teacher-community`، وراجع كل الملفات المخصصة لهذا المشروع في `supabase/project-manifest.json`. لا تنفّذ مجلد migrations المختلط كله. راجع `docs/DATABASE_DEPLOYMENT_AR.md` قبل تطبيق أي تغييرات على بيئة قائمة.

## 4. تعيين حسابك مديراً لمجتمع الأساتذة
1. افتح صفحة `https://gosvtmaroc.com/teacher-community.html`.
2. أنشئ حساباً جديداً ببريدك وكلمة مرور تختارها لمجتمع الأساتذة، وأكمل تأكيد البريد إن كان مفعلاً.
3. سجّل الدخول مرة واحدة حتى ينشأ مستخدم Auth.
4. في SQL Editor للمشروع الجديد نفّذ الاستعلام التالي بعد استبدال البريد ببريد حسابك:

```sql
insert into public.teacher_community_admins (user_id)
select id from auth.users
where lower(email) = lower('YOUR_ADMIN_EMAIL')
on conflict (user_id) do nothing;
```

5. سجّل الخروج ثم الدخول من جديد. سيظهر تبويب «إدارة المجتمع».

## 5. طريقة العمل
- يسجل الأستاذ في المشروع الجديد، وينشأ طلب عضوية pending.
- أنت توافق على الطلب من لوحة «إدارة المجتمع».
- بعد الموافقة، يستطيع الأستاذ رؤية المكتبة ورفع ملفات PDF وWord وPowerPoint وExcel وغيرها، ومشاركتها أو إبقاؤها خاصة.
- يستطيع الأستاذ المقبول تعديل/حذف موارده فقط؛ عند تعليق العضوية تتوقف صلاحيات الرفع والتعديل على بيانات الموارد وملفات Storage. المدير يشرف على كل الموارد ويستطيع إدارتها.
- التحميل يتم بروابط موقعة قصيرة الأجل من bucket خاص، وليس بروابط عامة.

## الصيغ والحجم
PDF, DOC, DOCX, PPT, PPTX, XLS, XLSX, ODT, ODP, JPG, JPEG, PNG, WEBP, TXT, ZIP.
الحد الأقصى 50 MB للملف.

## الملف المهني للأستاذ — تحديث 27 نوفمبر 2026
أُضيفت حقول الملف المهني إلى سجل العضوية الحالي دون إنشاء مشروع قاعدة بيانات جديد أو تغيير هوية الحساب. تشمل الحقول النبذة، المدينة والجهة، المستويات، المسالك، الاهتمامات والمهارات. تبقى هذه المعلومات مرئية لصاحب الحساب وإدارة المجتمع فقط؛ لم يُفعّل اكتشاف الملفات بين الأعضاء بعد.

ترحيل قاعدة البيانات المرتبط بالميزة هو `20261127000100_teacher_community_professional_profiles.sql`، وهو مخصص حصراً لمشروع `teacher-community`.

## موارد مصنفة ومفضلة — تحديث 27 نوفمبر 2026
أضيفت محلياً حقول المستوى والمسلك واللغة والسنة الدراسية والفصل/الدرس والمحور إلى موارد المكتبة، مع فلاتر وبحث محسّن. كما أضيفت مفضلة شخصية خاصة بكل حساب. يعتمد ذلك على الترحيل الإضافي `20261127000200_teacher_community_resource_metadata_and_favorites.sql`، وهو مخصص لمشروع `teacher-community` فقط. جدول المفضلة محمي بسياسات RLS، ولا يمكن للمستخدم رؤية مفضلات حساب آخر.

الواجهة والترحيل والاختبارات موجودة في المستودع، لكن لم يتم تطبيق الترحيل في Supabase البعيد أو اختبار CRUD عبر حسابات حية. راجع `docs/PHASE_3_RESOURCE_LIBRARY_AR.md` قبل التشغيل؛ يجب التحقق من migrations في staging أولاً، وعدم تطبيق الملف على مشروع الطلاب.

**قبل نشر تغييرات الواجهة أو قاعدة البيانات الخاصة بالمجتمع:**
1. حدّد حالة migrations الفعلية في مشروع المجتمع وقارنها بالقائمة المعتمدة؛ لا تفترض أن وجود الملف في Git يعني تطبيقه على Supabase.
2. خذ نسخة احتياطية، وطبّق الترحيل المطلوب في مشروع staging أولاً. اختبر الملف المهني بحسابات معتمدة وقيد المراجعة ومدير، واختبر رفع/تعديل بيانات المورد والفلاتر والمفضلة بحسابين منفصلين.
3. تحقق من أن RLS تمنع العضو من الاطلاع على ملف مهني أو مفضلة حساب آخر، أو حفظ مورد خاص/مخفي.
4. لا تعِد تنفيذ migrations مطبقة سابقاً، ولا تطبق migrations الخاصة بمشروع `main` على مشروع المجتمع.
5. بعد التحقق من schema وسياسات RLS في staging، انشر ملف الواجهة المتوافق. هذا المستودع لا يملك اتصالاً إدارياً بقاعدة Supabase الحية، لذلك لم يُنفّذ الترحيل عن بُعد.

## الأمان
- لا تضع service_role أو secret key في JavaScript.
- مفتاح Publishable فقط في الواجهة، مع اعتماد RLS وسياسات Storage.
- لا تغيّر أدوار حسابات الموقع الحالي أو جداول الطلاب.
- قبل الإعلان عن تفعيل النظام، اختبره بحساب مدير وحساب أستاذ تجريبي، وتحقق من منع الأستاذ من تعديل ملفات الآخرين.
