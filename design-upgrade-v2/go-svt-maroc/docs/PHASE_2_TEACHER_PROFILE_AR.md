# المرحلة الثانية — الملف المهني للأستاذ

**التاريخ:** 27 نوفمبر 2026
**النطاق:** بوابة مجتمع الأساتذة فقط. لا تغييرات على فضاء التلميذ أو مشروع Supabase الرئيسي.

## ما أُنجز

- إضافة تبويب «ملفي المهني» إلى لوحة مجتمع الأساتذة.
- نموذج لحفظ الاسم المعروض، الصفة المهنية، المؤسسة الاختيارية، المدينة، الجهة، نبذة قصيرة، المستويات، المسالك، الاهتمامات والمهارات.
- دعم الفواصل العربية واللاتينية في قوائم الاهتمامات والمهارات، مع إزالة التكرار وحدود للطول والعدد.
- تخزين المعلومات في صف العضوية الموجود نفسه؛ لا يوجد جدول أو مشروع قاعدة بيانات إضافي.
- إبقاء الملف خاصاً بصاحبه وإدارة المجتمع في هذه المرحلة. لم تُفعّل رؤية ملفات الأعضاء لبعضهم؛ يجب تنفيذ إعدادات الخصوصية والاكتشاف قبل تلك الوظيفة.
- توسيع واجهة الأعضاء والإدارة لتستخدم الحقول الجديدة، مع مسح النموذج عند تسجيل الخروج أو تبديل الحساب.
- إضافة قواعد SQL للتحقق من القيم، وسياسة تسمح بتعديل الصف الشخصي فقط، ومشغّل يمنع العضو من تغيير المعرّف أو حالة العضوية أو تاريخ الإنشاء. تبقى إدارة الموافقة بيد المدير.
- السماح للمدير بإنشاء صف ملفه الشخصي إذا لم يكن له صف عضوية سابق، دون تخفيف قواعد التسجيل العادي الذي يبقى `pending`.
- إضافة الترحيل إلى `supabase/project-manifest.json` تحت المشروع `teacher-community` فقط.

## اختبارات هذه المرحلة

- `npm test` — **121 اختباراً ناجحاً، دون إخفاق**.
- `npm run test:browser` — **5 اختبارات ناجحة**، بما فيها اختبار RTL والتنقل وعرض النموذج على شاشة الهاتف والحاسوب.
- `python3 scripts/check-site.py` — ناجح.
- `python3 scripts/check-teacher-community-security.py` — ناجح.
- `python3 scripts/check-migration-rls.py` — ناجح.
- `python3 scripts/migration-plan.py --check` — ناجح؛ كل ترحيل مُسند إلى مشروع واحد فقط.
- نُفّذ اختبار SQL للمخطط وسياسات الصفوف في PostgreSQL معزول (PGlite)، شمل منع تغيير العضوية، منع قراءة/تعديل صف زميل، دعم العضو قيد المراجعة، صلاحية المدير، وحدود الحقول.

نجاح الاختبارات لا يعني تطبيق الترحيل على Supabase الحي. تعذر اختبار الكتابة على Supabase حقيقي لعدم وجود اتصال إداري أو مشروع staging متاح في هذه الجلسة.

## قبل النشر

1. راجع حالة migrations الفعلية في مشروع `teacher-community` وخذ نسخة احتياطية.
2. طبّق `20261127000100_teacher_community_professional_profiles.sql` في staging بعد التأكد من ترتيب migrations السابقة.
3. اختبر بحسابات منفصلة: عضو معتمد، عضو قيد المراجعة، مدير، وحساب مجهول.
4. انشر الواجهة بعد نجاح التحقق من قاعدة staging؛ الواجهة الجديدة تعتمد الحقول التي ينشئها هذا الترحيل.
5. لا تنفذ هذا الملف على مشروع Supabase الرئيسي ولا على مشروع الطالب.

## التالي المقترح

إثراء بيانات الموارد بمستوى الدراسة والمسلك واللغة والمحور والسنة الدراسية، مع فلاتر بحث وفهارس مناسبة. بعد ذلك يمكن بناء لوحة مؤشرات حقيقية مبنية على موارد العضو، ثم إضافة المفضلة. يجب تصميم مشاركة الملف الشخصي على نحو مستقل قبل السماح للأعضاء الآخرين باكتشافه.
