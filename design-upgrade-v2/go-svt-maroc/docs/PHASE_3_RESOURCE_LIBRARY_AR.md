# المرحلة التالية — إثراء مكتبة مجتمع الأساتذة

**الحالة: مكتملة محلياً ومجتازة للاختبارات المتاحة؛ غير منشورة على Supabase أو GitHub.**

## ما أُنجز
- إضافة حقول تربوية اختيارية للموارد: المستوى، المسلك، اللغة، السنة الدراسية، الفصل/الدرس، والمحور.
- ربط هذه الحقول بنماذج رفع الموارد وتعديلها، وإظهارها كوسوم على بطاقات الموارد.
- إضافة فلاتر المكتبة للمستوى والمسلك واللغة والسنة الدراسية، وإدراج الفصل والمحور ضمن البحث النصي.
- إضافة مفضلة خاصة بحساب الأستاذ، مع قائمة ذات صفحات؛ يمكن حفظ الموارد المشتركة المنشورة وإزالة الحفظ.
- إضافة عدّاد للمفضلة في ملخص الموارد الشخصي.
- حماية جدول المفضلة بـ RLS: القراءة والحذف للحساب المالك فقط، والإضافة للحساب المقبول أو المدير فقط وللموارد المنشورة المشتركة المرئية. لا تتضمن المفضلة بيانات شخصية ظاهرة للآخرين.
- الحفاظ على جداول وهوية مشروع `teacher-community` الحالية، دون تعديل قاعدة الطلاب أو واجهة «فضاء التلميذ».

## قاعدة البيانات والتهيئة
الترحيل الإضافي هو:
`supabase/migrations/20261127000200_teacher_community_resource_metadata_and_favorites.sql`

وهو مخصص لمشروع `teacher-community` ومضاف إلى `supabase/project-manifest.json`. لم يُطبّق على أي قاعدة بعيدة؛ يلزم التأكد من المشروع وحالة الترحيلات وأخذ نسخة احتياطية قبل تطبيقه يدوياً في staging ثم production. لا تنفّذ الملف على مشروع الطلاب، ولا تعِد تطبيق migrations سبق تنفيذها.

## التحقق المحلي
- `node --check teacher-community.js` — ناجح.
- `npm test` — 132 اختباراً ناجحاً، تشمل قيود قاعدة البيانات وRLS والتحقق الفعلي من بناء فلاتر الموارد وقيم بيانات النماذج وإضافة/إزالة المفضلة مع تقييد الحساب وحماية تبديل الحساب أثناء طلب المفضلة.
- `npm run test:browser` — 6 اختبارات ناجحة، بما فيها تحقق واجهة الفلاتر ونموذج المورد ولوحة المفضلة RTL على الهاتف. هذه الاختبارات لا تتصل بمشروع Supabase حي لاختبار CRUD للمفضلة أو الموارد.
- `scripts/check-site.py`, `scripts/check-teacher-community-security.py`, `scripts/check-migration-rls.py`, `scripts/migration-plan.py --check`, و`git diff --check` — ناجحة.

## ما يلزم قبل إعلان التفعيل الفعلي
1. تطبيق الترحيل بعد مراجعة manifest وحالة المشروع في بيئة staging.
2. إجراء اختبار تكاملي بحساب مدير وعضو معتمد: رفع مورد بالحقول، تعديله، تطبيق الفلاتر، وحفظ/إزالة مورد من المفضلة.
3. اختبار حساب غير مقبول/مجهول ومحاولة الوصول إلى موارد غير مشتركة، والتأكد من رفضها بواسطة RLS وسياسات Storage.
4. التحقق بصرياً على الهاتف ثم نشر نسخة الواجهة المطابقة للترحيل.

حتى إجراء هذه الخطوات، الميزة مدمجة في الشيفرة ومختبرة محلياً، لكن تشغيلها على الخدمة الحية غير مؤكد. لم تُنشر أي تغييرات إلى GitHub ولم يُنفّذ أي ترحيل عن بُعد.
