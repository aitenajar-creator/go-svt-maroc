# تسليم «مساحتي» المتقدمة — Go SVT Maroc

## الحالة

هذه حزمة مصدر محلية تراكمية: تشمل إصلاحات المراجعة السابقة والمنصة الجديدة. **لم تُرفع إلى GitHub، ولم تُنفذ ترحيلات على قاعدة بيانات الإنتاج.** أساسها الالتزام:

`83ade7b4c7cfccbea96716dc46e58da30fe51342`

المعاينة تعمل محليًا بملف تجريبي واضح التسمية، دون اتصال ببيانات الإنتاج. المكتبة تستعمل الملفات الحقيقية في المستودع؛ لا تحتوي المعاينة على نقط أو إنجازات مصطنعة عند البداية.

## ما تحتويه

- `go-svt-maroc-student-platform-v2.patch`: جميع التغييرات منذ الالتزام الأساس، بما فيها حزمة الإصلاحات السابقة.
- `files/`: الملفات المعدّلة والجديدة فقط، بمساراتها الأصلية داخل المستودع.
- `VALIDATION.json` و`validation-log.txt`: نتائج التحقق المحلي وفحص تطبيق patch.
- `preview-desktop.png` و`preview-mobile.png`: لقطات للواجهة المحلية، وليستا واجهة بديلة عن التطبيق.
- داخل المصدر: `docs/STUDENT_PLATFORM_AR.md` لدليل الميزات والتشغيل والتقييم والحدود، و`docs/DATABASE_DEPLOYMENT_AR.md` لمتطلبات قاعدة البيانات.

لا تتضمن الحزمة نسخًا من ملفات PDF الأصلية غير المعدلة أو `node_modules` أو `.git`. عند تطبيقها على المستودع تبقى تلك الملفات في أماكنها.

## تطبيق التغييرات

ابدأ بفرع مراجعة من نسخة نظيفة، لا بنشر مباشر إلى الإنتاج:

```sh
git clone https://github.com/aitenajar-creator/go-svt-maroc.git
cd go-svt-maroc
git switch -c feature/advanced-student-platform
git apply --check /PATH/TO/go-svt-maroc-student-platform-v2.patch
git apply /PATH/TO/go-svt-maroc-student-platform-v2.patch
npm ci --ignore-scripts
npm run build:catalog
npm test
npx playwright install --with-deps chromium
npm run test:browser
npm run dev:student
```

افتح `http://127.0.0.1:8000`. لإتاحة معاينة داخل بيئة شبكية، استخدم:

```sh
npm run dev:student -- --host 0.0.0.0
```

إذا طُبقت الحزمة السابقة بالفعل، أو تغير المستودع بعد الالتزام الأساس، فقد يتطلب التطبيق دمجًا ومراجعة للفروق. لا تستخدم تطبيقًا قسريًا أو استبدالًا شاملاً يمحو العمل الأحدث. `git apply --check` لا يغيّر الملفات.

بديل واجهة GitHub: ارفع محتويات `files/` إلى المسارات المناظرة **في فرع جديد**؛ لا ترفع مجلد `files` نفسه داخل الموقع. راجع الفروق قبل إنشاء commit من حسابك المخوّل.

## قبل تفعيل حسابات الإنتاج

1. راجع المخطط التأسيسي الحقيقي للمشروع الرئيسي. لم يتوفر هذا المخطط كاملًا، ولم يُخمن بديل له.
2. إذا لم تكن ترحيلات المراجعة السابقة مطبقة، اختبر ثم طبّق `20261125000100` و`20261125000200` و`20261125000300` بترتيبها على المشروع الرئيسي.
3. اختبر ثم طبّق `20261126000200_student_learning_platform.sql`، كوحدة ترحيل كاملة، على **المشروع الرئيسي فقط**.
4. تحقق من منع التلميذ من تعديل الأدوار أو الملف الدراسي، ومن سلوك Auth وPostgREST وStorage الفعليين بحسابات staging منفصلة.
5. افتح لوحة المدير، ثم «منصة التعلّم والاختبارات». راجع الأسئلة وأجوبتها وملاءمتها قبل نشر أي بنك.
6. انشر الواجهة بعد نجاح الترحيلات والتحقق. الصفحات التجريبية وحزمتها مستبعدة من ناتج الإنتاج.

## حدود مهمة

- التدريب المحلي معلن بوصفه تدريبًا ذاتيًا؛ التقييم المُدار يحتاج خدمة مهيأة وتسجيل دخول.
- الاختبارات الخادمية تحفظ مفاتيح الإجابة وتوقيت النهاية على الخادم، لكنها ليست مراقبة امتحانات أو شهادة رسمية. الأسئلة المنقولة من مصدر عام قد تكون أجوبتها متاحة خارج API.
- التجارب نماذج افتراضية تعليمية وليست قياسات مختبرية حقيقية.
- بعض المسالك قليلة المحتوى في المصدر؛ يُظهر التطبيق الموجود فعلًا دون ملء الفراغ بامتحانات أو دروس وهمية.
- اختبارات SQL تعمل على PGlite ومخطط اختبار معزول، وليست إثباتًا لإعدادات الإنتاج. لم ينفذ نشر GitHub Pages أو بناء Jekyll الإنتاجي الكامل من هذه البيئة.
