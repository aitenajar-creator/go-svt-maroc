# بوابة التحقق قبل تفعيل منصة التعلّم الجديدة

هذه الوثيقة تسجل شروط الانتقال من الحزمة التجريبية `design-upgrade-v2/files` إلى الموقع المنشور. لا تنفّذ أي SQL ولا تغيّر إعدادات الإنتاج.

## نتيجة فحص الإنتاج — 2026-11-26

فُحص مشروع Supabase الرئيسي `faztvkeyrxvmjzzfuyiu` باستعلامات قراءة فقط.

| الاعتماد | النتيجة |
|---|---|
| `student_progress` و`student_notes` و`student_favorites` و`student_learning_state` | موجودة |
| `learning_resources` | غير موجود |
| `learning_assessments` | غير موجود |
| `learning_attempts` | غير موجود |
| `gosvt_platform_start_assessment` | غير موجود |
| `gosvt_platform_save_answers` | غير موجود |
| `gosvt_platform_submit_assessment` | غير موجود |

لا توجد بيئة staging مستقلة مؤكدة ضمن مشاريع Supabase المتاحة وقت الفحص. مشروع مجتمع الأساتذة مستقل ويجب ألا يُستخدم كبيئة اختبار للمنصة الطلابية.

## شروط التفعيل

- [ ] إنشاء/تحديد مشروع staging مستقل للمشروع الرئيسي، دون نسخ بيانات شخصية حقيقية للطلاب.
- [ ] استخراج baseline موثوق للمخطط الحالي: الجداول، القيود، الفهارس، السياسات، الدوال، المشغلات، Auth وStorage.
- [ ] مراجعة ترتيب الترحيلات؛ يوجد تعارض في الطابع الزمني `20261125000400` بين ترحيل المنصة وترحيل موجود في سجل المشروع. يجب إعادة ترقيم ترحيل المنصة وفق تسلسل واضح قبل أي تطبيق.
- [ ] تشغيل ترحيلات المشروع الرئيسي فقط على staging، بعد مراجعة baseline، وبالترتيب الموثق في `docs/STUDENT_PLATFORM_AR.md`.
- [ ] اختبار RLS على الأقل لحالات: تلميذ، مدير، مستخدم غير مسجل، وحساب آخر؛ والتحقق من عدم كشف مفاتيح الإجابات أو السماح بتعديل موارد الآخرين.
- [ ] اختبار بدء الاختبار، حفظ الإجابات، انتهاء الوقت، التسليم، منع التكرار، وحساب النتيجة من الخادم.
- [ ] اختبار توافق بيانات التلميذ الحالية: التقدم، الملاحظات، المفضلات، الخطة، والملف الأكاديمي.
- [ ] تشغيل اختبارات Node وPlaywright وفحوص الوصول والبناء على الفرع.
- [ ] مراجعة التغييرات المرئية في معاينة غير إنتاجية، ثم اعتماد نشر منفصل.
- [ ] لا يُنفّذ أي ترحيل إنتاجي إلا بعد نسخة احتياطية وخطة تراجع وموافقة صريحة.

## حدود الأمان

- لا تشغّل ترحيلات الحزمة على قاعدة الإنتاج مباشرة.
- لا تستخدم مشروع مجتمع الأساتذة أو مفاتيحه للمنصة الطلابية.
- لا تضع `service_role` أو كلمات مرور قواعد البيانات في ملفات المستودع أو المتصفح.
- لا تعتبر اختبارات PGlite أو البيانات الوهمية دليلاً على سلامة سياسات الإنتاج.
- لا ترفع صفحات المعاينة أو ملفات SQL أو الاختبارات إلى Pages على أنها واجهة عامة.
- يجب أن تبقى واجهة الطالب الحالية عاملة إلى أن تجتاز المنصة الجديدة جميع الشروط أعلاه.

## القرار الحالي

**غير جاهزة للتفعيل الإنتاجي.** الحزمة يمكن مواصلة تطويرها ومراجعتها في فرع منفصل، لكن لا ينبغي ربط واجهاتها بخدمات الإنتاج قبل إغلاق شروط هذه البوابة.
