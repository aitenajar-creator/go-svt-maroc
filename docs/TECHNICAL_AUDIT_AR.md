# التدقيق التقني الأولي لمنصة GO SVT Maroc

تاريخ التدقيق: 12 نوفمبر 2026  
المستودع: `aitenajar-creator/go-svt-maroc`  
الفرع المرجعي: `main`  
نطاق التدقيق: ملفات المستودع، هيكل الصفحات، ملفات JavaScript/CSS، migrations، وسجلات GitHub Actions المتاحة. هذا تدقيق للمصدر البرمجي وليس اختبار اختراق أو اختباراً شاملاً للنسخة الحية أو لقواعد Supabase.

## 1. ملخص الحالة

- المستودع يحتوي على 489 مدخلاً في شجرة Git وقت التدقيق.
- الفرع الافتراضي هو `main`، والمستودع متاح للقراءة والكتابة عبر اتصال GitHub.
- آخر تغييرات تحسين الترويسة، نبذة المؤسس، ومنع تكرار الرفع مدمجة في `main` عبر PRs #87 و#86 و#88.
- أحدث عمليات التحقق والنشر التي تمت مراجعتها كانت مكتملة وناجحة على commit `04a09e40111bf8d67d58cff338d88303b2726418`.
- المشروع ما زال تطبيقاً ثابتاً مبنياً أساساً على HTML/CSS/JavaScript، مع استخدام Supabase للمصادقة والبيانات والتخزين في أجزاء من المنصة.
- مجتمع الأساتذة له إعداد Supabase منفصل عن المشروع الأساسي، ويجب الحفاظ على هذا الفصل.

## 2. المكونات الموجودة

### الموقع الرئيسي
- `index.html` والأنماط `styles.css`, `enhancements.css`, `visual-refresh.css`.
- المحتوى المنظم حسب المستوى والمسلك واللغة.
- الصفحة الرئيسية، الترويسة، التنقل، وملف نبذة المؤسس القابل للتحرير.

### فضاء التلميذ
- `student-space.js` وملفات التكامل والحساب والتقدم والتحليلات.
- وحدات للتقدم الدراسي، الملاحظات، المفضلة، خطة الدراسة، الاختبارات والتحليلات.
- ملفات migrations تتعلق بالاختبارات ودعم الأستاذ والقسم ومتابعة التلميذ.
- يجب اعتبار بيانات المستخدمين الحالية بيانات إنتاجية وعدم إجراء تغييرات مدمرة عليها.

### فضاء الأستاذ ومجتمعه
- `teacher-classroom.js` لإدارة الأقسام والتواصل والمتابعة.
- `teacher-community.html/js/css` لمجتمع تبادل الموارد.
- migrations مستقلة لمكتبة مجتمع الأساتذة وصلاحيات التخزين.
- لا يجوز دمج حسابات أو قواعد بيانات المجتمع مع حسابات المنصة الأساسية دون تصميم وترحيل موثقين.

### الإدارة
- `admin.html/js/css` لإدارة المحتوى.
- migrations لإدارة المحتوى الخاصة بالمدير، سجل التلاميذ، ملف المؤسس، ومنع تكرار الملفات.
- بصمة SHA-256 تمنع إعادة نشر الملف نفسه ضمن التصنيف والتصنيف الدراسي نفسه.

## 3. نتائج التحقق الأولي

| المجال | النتيجة |
|---|---|
| شجرة المستودع | تمت قراءتها |
| وجود فضاءات التلميذ والأستاذ والإدارة | مؤكد في المصدر |
| migrations الأساسية الحديثة | موجودة في المستودع |
| أحدث عمليات GitHub Actions المفحوصة | نجاح |
| وجود مفتاح service_role ضمن ملفات إعداد الواجهة المفحوصة | لم يظهر؛ ظهرت الكلمة في تعليقات تحذيرية فقط |
| اختبار شامل للنسخة الحية | لم ينفذ ضمن هذا التدقيق |
| اختبار فعلي لسياسات RLS لكل الجداول | يحتاج حسابات اختبار واتصالاً بمشاريع Supabase |
| اختبار بصري شامل على الهاتف والحاسوب | يحتاج متصفحاً فعلياً |

## 4. ملاحظات ومخاطر يجب معالجتها

1. توجد وثائق قديمة تصف المشروع بأنه لا يستخدم backend أو تسجيل دخول خادمي؛ هذه الوثائق لم تعد تعكس البنية الحالية بالكامل، وينبغي تحديثها تدريجياً.
2. تقرير Version 7 مؤرخ في 4 نوفمبر 2026 ويصف نسخة أقدم من بنية Supabase الحالية؛ لا ينبغي اعتباره تدقيقاً حديثاً كاملاً.
3. يجب إضافة اختبارات آلية لصلاحيات الأدوار: زائر، تلميذ، أستاذ، ومدير.
4. يجب التحقق من أن كل مسار Storage خاص أو عام بحسب متطلبات العمل، وألا تعتمد الحماية على إخفاء الأزرار في الواجهة.
5. يجب تحسين مراقبة أخطاء المزامنة ورفع الملفات، مع رسائل واضحة وسجل عمليات إداري.
6. ينبغي فحص الأداء وإمكانية الوصول وSEO والروابط الداخلية بصورة دورية.
7. لا يمكن التحقق من بيانات Supabase الحية أو تنفيذ migrations عليها من مستودع GitHub وحده.

## 5. خطة التنفيذ المعتمدة

### المرحلة A — تثبيت الأساس
- جرد المسارات والصفحات والوظائف.
- توحيد وثائق البنية الحالية.
- إعداد قائمة اختبارات عدم الانحدار.
- فحص الصلاحيات ومسارات التخزين.
- إعداد إجراء نسخ احتياطي واسترجاع موثق.

### المرحلة B — تحسين تجربة الاستخدام
- مراجعة الترويسة والقوائم على جميع أحجام الشاشات.
- تحسين التنقل بين الفضاءات دون ازدحام.
- تحسين حالات التحميل والخطأ والفراغ.
- تحسين التباين ولوحة المفاتيح ودعم قارئات الشاشة.

### المرحلة C — فضاء التلميذ
- تحسين لوحة القيادة والمكتبة.
- مراجعة دقة مؤشرات التقدم والنتائج.
- تعزيز البحث والتصفية.
- تحسين تجربة الاختبارات والمراجعة.

### المرحلة D — فضاء الأستاذ ومجتمع الأساتذة
- استكمال إدارة الأقسام والتكليفات والتقارير.
- تحسين مكتبة الموارد والبحث والتصنيف.
- تدقيق صلاحيات ملكية الملفات والإشراف.

### المرحلة E — المختبر الرقمي والتعلم الذكي
- إطلاق وحدات تفاعلية صغيرة قابلة للقياس.
- اعتماد محتوى علمي موثق ومتوافق مع المقرر المغربي.
- إضافة مساعد تعليمي بعد تحديد ضوابط الدقة والخصوصية.

## 6. قواعد السلامة أثناء التطوير

- لا حذف أو إعادة تسمية لمحتويات أو جداول إنتاجية دون خطة ترحيل واختبار.
- لا تعديل لأدوار المستخدمين من جهة العميل.
- لا وضع مفاتيح سرية أو service_role في ملفات الواجهة.
- كل تغيير بنيوي في قاعدة البيانات يمر عبر migration قابلة للمراجعة.
- كل ميزة جديدة تُطوّر في فرع مستقل وتُراجع قبل الدمج.
- يجب نجاح فحوصات JavaScript وJSON ومراجع الأصول قبل النشر.
- لا يُعلن نجاح ميزة قبل اختبارها في البيئة المناسبة.

## 7. حدود هذا التقرير

هذا التقرير يمثل خط أساس أولياً من ملفات GitHub وسجلات Actions المتاحة. لا يثبت وحده سلامة قواعد Supabase الحية أو صحة كل تدفقات الاستخدام أو جودة العرض على كل جهاز. يجب استكمال هذه الاختبارات على مراحل قبل اعتبار المنصة مدققة بالكامل.
